# 手触り（juice）の正典

> 2026-08-14 オーナー指示：「単純に触ってて楽しいを感じれるためのパワーアップは、有名作品からどんどん取り込んでいく」。
> これは**常設の方針**であり、特定フェーズの作業項目ではない。新機能を作るたびに本書を見て、手触りの負債を残さないこと。
> 演出の実装値の一次資料は `assets_src/codex_consult_rogue.md` [D]（Reaction Director）。本書はその上位方針。

## 0. 原則

1. **無反応をなくす**。すべての入力・すべての消滅に、音・光・動き・数字のいずれかが即座に返る
2. **メリハリ**。通常は静か、決め所で一気に。常時派手は疲れる
3. **判定を隠さない**。エフェクトが駒の識別を長時間覆ってはいけない
4. **有名作を実際に触って盗む**。「なぜ良いか」を言語化してから移植する
5. **応答は速く、鑑賞はゆっくり**（2026-08-15 オーナー観察。RM実測より）。
   - 自分の操作への反応（スワップ→最初のポップ、落下）は最速級に
   - 盤面が勝手に進む時間（連鎖・起爆）は**ゆっくり**。消えていく駒を**しっかり眺める時間**がご褒美。
     RMは連鎖が何段続いても拍を600〜800msに保つ。「連鎖ほど加速」は**誤った設計だった**
     （読めない霞になり、知見の発火や破片の飛翔という見せ場を自分で潰す）
   - 遅さが「待たされる時間」にならないのは**入力ロックがない**から。眺めるか・次を打つかはプレイヤーが選ぶ。
     途中入力で前の演出を切ってスナップするのも禁止（演出は重なって続く）

## 1. オーナーが名指しした要素（優先実装）

### ① Royal Match の駒の動き
実際にプレイして秀逸と評価された点：
- 駒の落下・スワップに**重みと弾み**がある（等速で動かない。着地で軽く沈んで戻る）
- 消える瞬間に**わずかに膨らんでから弾ける**
- 盤面全体が常に微細に呼吸している

→ 実装：落下は `easeOutBounce` 気味の着地、消滅は「膨張→弾け」の2段、待機中の駒に極小の呼吸（振幅1〜2px・周期2〜3秒・位相を駒ごとにずらす）。

### ② 目標が壊れるアニメーション
Royal Match の白眉。目標物（箱・氷など）が壊れると：
- 派手に砕けて破片が飛ぶ
- **破片や収集物がHUDの目標カウンターへ飛んでいく**（獲得の実感）
- カウンターが受け取って跳ねる

→ 実装：目標達成物が壊れたら、①その場で破砕（破片＋粉塵）②小さなアイコンがターゲット表示へ**弧を描いて飛ぶ**（300〜450ms）③着弾でカウンターが跳ねる＋数字が更新。**現状は数字が黙って減るだけ**なので、ここは大きな伸びしろ。

### ③ 触覚フィードバック（振動）
消すたびに小さく振動する。連鎖が伸びるほど強く。

**技術的な制約（正直に記録）**：
- Android Chrome：`navigator.vibrate()` で可能。**確実に効く**
- **iOS Safari：Vibration API 非対応**。iOS 18 以降で `<input type="checkbox" switch>` を label 経由でプログラム的に叩くと触覚が返る、という抜け道が報告されているが**正式APIではなく将来壊れうる**
- → 実装方針：`navigator.vibrate` があれば使う。無ければ iOS の抜け道を試す。**どちらも失敗しても無音で成立**させる（機能の前提にしない）
- パターン案：通常消し 8ms / 特殊駒生成 15ms / 爆発 25ms / 連鎖5以上 30ms＋間隔

### ④ 常時アニメーション（将来）
**特に敵**。止まっている敵は「置物」に見える。
- 敵：呼吸・瞬き・触角や尾のゆらぎ・インテント直前のわずかな身構え
- 駒：極小の呼吸（上記①）
- UI：ランタンの炎ゆらぎ（実装済み）、ドラフトカードの微かな浮き
- 背景：層テーマごとの遅い視差／光の明滅

→ 実装方針：**共有の idle ティッカー**を1本用意し、各オブジェクトが位相オフセットを持って参照する（個別 tween を大量に走らせない）。低価格端末で重くなったら idle だけ間引く。

## 2. 実装済み（`codex_consult_rogue.md` [D] 由来）

- 特殊駒の誕生演出（吸引→白コア→35msヒットストップ→easeOutBack着地）
- 爆発の3層構造＋規模別ヒットストップ（30/45/65ms）＋減衰する揺れ
- 連鎖テンポ＝**一定拍 `CHAIN_BEAT`（600ms・無加速）**。当初の加速カーブ（520→220ms）は
  2026-08-15 のRM実測（`assets_src/rm_tempo.md` §3：~620ms一定・無加速）により誤設計と確定し廃止（§0-5）
- 見える落下（`FALL_COEF=195`·√dist、上限390ms。RM実測 ~300ms/1-3行。一定拍の後半を落下の移動が埋める）
- 割込時の並行続行（§0-5「前の演出を切ってスナップするのも禁止」の実装。play() 冒頭の
  completeChannel('board') 全断を廃止し、装飾FXの予約は 'fx' チャンネル・新しい手が触る駒だけ選択的 snap）
- swarm撃破のドミノ伝播
- レイヤー4分割・粒子プール・ビュー専用シード
- **補充は剛体トレイン**（2026-08-15）：同じ拍・同じ列の補充駒は、着地行の並びを保った1マス間隔で
  盤の上空に整列し、同じ遅延・同じ所要時間で一斉に落ちる。個別落下（全駒が同一点に湧き行あたり14msずらし）は
  列内の密着・追い越し・湧き点のスタックを生むため禁止。pieceLayer は盤矩形でマスクし
  「枠の奥から降ってくる」に見せる（王道3マッチの標準）
- **決着画面は盤面静止後**：勝利/遭難の画面は view.isQuiet() を待ってから出す（連鎖に被せない）
- **割込時は前の手を「切らずに早送り」**（2026-08-15）：新しい手が始まったら前の手の未開始予約を
  一様に0.45倍へ時間圧縮（compressChannel）。順序が保存されるので演出は全部再生される。
  盤内の落下も同列・同拍は同遅延・同時間の剛体（columnFalls）＝距離差による追い越しを禁止

## 4. 検証

手触りは静止画では判定できない。**必ず動画で確認する**（`motion-capture` スキル、または Playwright の録画）。
「音を消した録画を第三者が見て、何が起きたか説明できるか」を合格条件にする。
