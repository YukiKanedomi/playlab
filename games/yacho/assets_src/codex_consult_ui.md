# モバイルWeb版 UI/UX・画面構成コンサルテーション

## [A] 画面構成の再設計

### 結論

**現行画面は、オーナー自身のコンセプトシートが示した美術には近づいているが、ゲームの意味は旧作のままである。** 大きな「ターゲット」札とスコア札は、手数内に指定物を集める旧レベル制では主役だった。しかし現在の勝敗は「10層を降り、敵を倒し、共有HPを守り、強化の因果を育てる」ことで決まる。勝敗に使わない情報が上段を占有し、勝敗に使うHP・現在層・敵の次行動・所持強化が周縁へ追いやられている。

`user_v3_1.jpg` と `user_v3_3.jpg` は、上から「小さなHUD／世界とキャラクター／大きな盤面／補助操作」という明快な縦構成である。現行も外形だけはこれを踏襲しているが、各領域の役割がローグライクへ更新されていない。ここは正面から作り直すべきである。

### 推奨プレイ画面：縦方向のバンド予算

基準はCSSの可視ビューポート高（`100dvh`）とし、上端・下端safe areaを含めて次の比率を固定する。390×844pxなら、1%は約8.4pxである。

| 高さ範囲 | 予算 | 配置するもの | 実装指示 |
|---|---:|---|---|
| 0〜3% | 3% | 上端safe area | 背景のみ。ノッチへ文字・ボタンを入れない |
| 3〜12% | 9% | ランHUD：左`深度 7/10`、中央〜右にHPゲージ、右端にメニューボタン | 1行に限定。旧ターゲット札、スコア、独立した戻るボタンは置かない |
| 12〜38% | 26% | 遭遇帯：探窟家バスト、`残敵`小チップ、次行動要約。ボス時はボス名＋ボスHP＋`あと2手で攻撃` | キャラを装飾ではなく状態の語り手にする。被弾予告では警戒表情／赤い縁光を出す。通常敵の全情報はここへ詰めない |
| 38〜84% | 46% | 8×8盤面 | 実サイズは`min(92vw, 44dvh)`、水平中央。バンド内上下に各1%以上の空きを確保。端末比率が変わっても上端を38%付近に固定する |
| 84〜92% | 8% | 所持強化「ビルドドック」 | 盤面外枠との間を`max(8px, 1dvh)`空ける。アイコン36〜40px、タップ領域44px以上。横スクロール。右端に`野帳`ボタン |
| 92〜100% | 8% | 下端safe area＋背景の余韻 | 常設の重要情報は置かない。短い発火集計（例：`胞子繁殖 ×7`）だけを一時表示してよい |

横幅は左右4vwを基本余白とし、盤面だけ最大92vwまで使う。ランHUDは`23% / 57% / 20%`の3列、遭遇帯の文字は左右各5vw以内に収める。高さが700px未満の端末では遭遇帯を22%へ縮め、盤面上端を34%へ繰り上げる。ただし盤面とビルドドックの8px間隔は削らない。

この構成で、プレイ画面に常駐させる情報は「どこまで潜ったか」「あと何発耐えられるか」「今なにと戦っているか」「どんなビルドか」の4つになる。これは現在のゲームの意思決定と一致する。

## [B] HPの見せ方

### 現行メダリオンの評価

円形メダリオンはオーナー案の造形としては魅力がある。しかしHP表示には不向きである。

- 円の中に大きな現在値と小さな`現在 / 最大`を重ね、同じ情報を二重表示している。
- 数字が2桁になるとラベル・縁飾り・最大値が競合し、すでに窮屈である。最大HPが将来増えればさらに破綻する。
- 円形数字は「20から16へ減った」ことを読む必要があり、残量の比率を周辺視野で掴めない。
- 被弾の軌跡が左上の小点へ吸い込まれるため、画面の主圧力であるHP減少が弱く見える。

### 3案の比較

| 方式 | 長所 | 短所 | 判定 |
|---|---|---|---|
| 20個の分割ピップ | 1ダメージ単位が正確。敵の2〜3ダメージも数えやすい | 20個は小さくなり、将来の最大HP増減に弱い。細かい光がHUDを騒がしくする | 単独採用しない |
| 横長HPバー | 残量を一瞬で読め、最大HP変更にも強い。ダメージ予告を重ねやすい | そのままだと汎用的で、洞窟探検の個性が薄い | 機能の土台として最適 |
| ランタンの油 | 世界観との結び付きが強く、減る恐怖を演出しやすい | 液面だけでは正確な残量が読みにくい。縦ランタンは上段を圧迫する | 比喩としてバーへ組み込む |

### 推奨：目盛り付き「探窟灯の油槽」バー

**横長バーを採用し、外装だけを真鍮製ランタンの油槽にする。** 機能はバー、読みの補助は5区画の目盛り、個性はランタンの比喩で受け持つ。20個のピップを並べるのではなく、4HPごとの5区画にし、数値`16 / 20`を必ず併記する。

- 配置：ランHUDの中央列。左端約28vw、上端`safe-area + 8px`。
- サイズ：幅`clamp(190px, 54vw, 248px)`、高さ`clamp(34px, 4.6dvh, 42px)`。
- 中身：左に小さなランタン炎、中央に油量、右端内側に`16 / 20`。ラベル`HP`またはハートを小さく添え、「油そのものがHP」と誤認させない。
- 目盛り：5区画の縦刻線。正確な1HPは数値で読み、25%単位は周辺視野で読む。
- 色：通常は暖かな琥珀〜蜂蜜色。背景とのコントラストを確保するため、油槽の背面は濃い焦茶。緑＝安全、赤＝危険という色だけの符号化はしない。

被弾時は、まず予告ダメージ分を半透明の「失う予定量」として0.4秒表示し、攻撃着弾でその部分を右端から抜く。例：16HPで3ダメージなら、`16 / 20`のバー上に13までの実油量と、13〜16の点滅する斜線領域を予告する。着弾時は80msの白い芯、180msの油揺れ、数値横に`−3`、キャラの被弾反応を同期させる。HPバー自体を大きく移動させず、2px程度の短い横揺れに留める。

低HPは25%以下、現仕様なら5以下で開始する。色変化だけにせず、次の3点を同時に使う。

1. 油槽の5区画中、最後の1区画だけになる。
2. ランタン炎が不規則に小さくなり、枠に細い亀裂状の明滅が入る。周期は1.4〜1.8秒で、常時高速点滅は避ける。
3. `瀕死`の文字ではなく、次に予告されている敵ダメージが致死なら`次の攻撃で倒れる`を遭遇帯へ明記する。

メダリオン資産は捨てなくてよい。現在層の小型バッジ、またはマップ上の現在地点へ転用すると、オーナー案の意匠を保ったまま役割を正せる。

## [C] 学ぶべきルールの情報設計

### 中核：一つの「野帳シート」に統合する

敵、強化、特殊駒、用語を別々のポップアップで作らず、画面下から出る共通ボトムシートを1コンポーネントとして実装する。高さは通常48dvh、詳細文が長い場合は最大72dvh。上部に対象アイコン、名前、種別、右上に×、本文はスクロール可能とする。背景タップ、×、下スワイプ、同じ対象の再タップで閉じる。開いている間は盤面入力だけを停止する。

現在の`showUpgradePopup()`と`BoardView.showEnemyTooltip()`はすでに「時間で消さない」方向へ改善されているが、位置・枠・入力管理が別々である。この重複が、左欠け資産や挙動差を再発させる。共通化が必要である。

左端が欠ける強化説明は、単なる座標調整では直さない。`ui_card`等の一枚絵を内容高に合わせて伸縮する方式をやめ、中央の羊皮紙地を9-slice、四隅と見出し帯を独立スプライトにする。内容安全域は左右24px以上、375／390／430px幅と1.0／1.25 DPRで四辺が見えることを自動撮影で確認する。

### 表面ごとの情報と操作

| 表面 | 常時見せるもの | 開き方 | シート内で見せるもの |
|---|---|---|---|
| プレイ中・ビルドドック | 所持強化アイコン、回数条件なら`1/2`、発火時の短い点灯 | アイコンをタップ | 強化名、系統、`条件→効果`、進捗、相性が成立している所持強化、獲得時効果。前後の所持強化へ横スワイプ可能 |
| ドラフト中・所持欄 | 所持強化アイコン、所持数、主系統の内訳 | アイコンをタップ。`一覧`で全画面のビルド一覧 | 同上。候補カードを隠さず、シートを閉じると同じスクロール位置へ戻る |
| 特殊駒 | 盤面上は現物の形と向き。野帳には4種の早見アイコン | ビルドドック右端の`野帳`→`特殊駒`。盤面上では長押しをショートカットにしてもよい | 銛：向きの1列／1行を消す。羽虫：目標へ飛び周囲を壊す。火壺：5×5を壊す。星珠：同色をすべて消す。2個組合せも図で見せる |
| 敵 | 個体HP、次行動の種別アイコン、残り手数 | 敵本体またはインテントバッジをタップ | 名前、HP、次行動、与ダメージ、妨害内容、倒し方、状態異常。ボスは後退条件も表示 |
| 用語 | 本文中の用語に点線下線＋小さな`?` | 用語そのものをタップ | 2〜3行の定義＋小図。さらに詳しい項目だけ`野帳で見る`を置く |

特殊駒は通常タップで発動する仕様なので、**説明と発動を同じ単タップへ割り当ててはいけない。** 主導線は常設の`野帳→特殊駒`とし、盤面長押しは任意の近道に留める。初回生成時だけ、操作を止めない小さなコーチマーク`野帳で効果を確認`を出す。

候補カードの本文に用語リンクを置く場合、カード全体タップで即取得する現方式は危険である。候補カードのタップは「選択状態」にするだけにし、取得は画面下の`この強化を取る`ボタンで確定する。用語をタップしたイベントはカード選択へ伝播させない。説明を閉じても選択状態は保持する。

### 用語集に必要な項目

最低限、次を登録する。初見語、挙動が名前だけでは確定しない語、状態の持続先が分かりにくい語を優先する。

- 基本：`マッチ`、`連鎖`、`隣接`、`変換`、`生成／置く／降らせる`、`特殊駒`、`臨界`
- 4系統：`植物`、`鉱物`、`ギア`、`遺物`、`異種シナジー`
- ビルド：`強化`、`条件`、`効果`、`相性`、`獲得ボーナス`、`スターター効果`、`ギア起動`、`充填`、`再発動`、`コピー`
- 盤面状態：`胞子`、`爆発鉱石`、`甲殻`、`毒胞子`、`封鎖`
- 戦闘：`敵インテント／行動予告`、`攻撃`、`妨害`、`残り手数`、`全体攻撃`、`後退`
- 特殊駒：`銛`、`羽虫`、`火壺`、`星珠`

`植物マッチ時`のような複合表現では、`植物`と`マッチ`を別々のタップ領域に乱立させない。文として意味のある`植物をそろえて消す`を本文にし、必要な語だけリンクにする。リンクは色だけに頼らず、点線下線と`?`を併用する。

## [D] ドラフト画面 v2

### 現行の問題

現在の3枚カードは美術的には整ってきたが、まだ「候補の文章を上から読む画面」である。所持強化が見えないため、プレイヤーは相性行に名前が出ても、その能力を思い出せない。さらに金文字の相性行は羊皮紙と明度が近く、見つけにくく読みにくい。候補をタップすると即取得するため、用語説明や比較操作を追加する余地もない。

`相性`が出ていることと、なぜ繋がるかは別問題である。`菌糸の目覚め`という金文字だけでは、候補が何を受け取り、何を次へ渡すか読めない。

### 推奨レイアウト

| 高さ範囲 | 内容 |
|---|---|
| 0〜9% | タイトル`深度6 踏破 — 強化を1つ選ぶ`。右上に野帳 |
| 9〜20% | 所持強化ストリップ。40pxアイコン、横スクロール、左に`所持 5`、右に`一覧`。主系統の小さな内訳`植物3・鉱物1・ギア1` |
| 20〜82% | 候補カード3枚。各18%、カード間4%。カードは比較用の同一構造を保つ |
| 82〜96% | 選択中の接続要約＋確定ボタン。未選択時は`カードを選んで比較`、選択後は`胞子繁殖 → 根食い鉱：爆発鉱石を作れる`と`この強化を取る` |
| 96〜100% | 下端safe area |

各候補カードは次の順にする。

1. 左に固有アイコン36〜40px。右に系統名、強化名。
2. 中央に`条件`と`効果`。各1因果、最大2行。用語リンクは点線下線。
3. 接続がある場合だけ「接続バッジ」。
4. 必要な強化だけ、最下段に小さな`獲得ボーナス`帯。

### 読めるシナジー表示

金文字を羊皮紙へ直接置くのをやめる。推奨は、濃い深界ティール`#1E4D5C`の角丸バッジに古紙色`#F4E8CF`の文字を載せ、左に鎖アイコンを付ける方式である。枠線も2px付ける。これなら色覚だけでなく、**専用形状・鎖記号・`接続 2`という文字**で相性の有無が分かる。

表示は名前の羅列ではなく因果にする。

> 🔗 **接続 2**　胞子繁殖で作る胞子 → この強化で毒にする

カード内に収まらなければ`接続 2`だけを出し、選択時の下部比較欄で上の一文を見せる。相性なしは空欄にし、灰色の`相性なし`でカードを罰のように見せない。

### 強化アイコン体系

カテゴリ駒の流用だけでは、10個並んだときに個々の強化を判別できない。最終的には20強化すべてに固有グリフを作る。

- 外周：系統を示す。植物＝蔓の円、鉱物＝角張った結晶枠、ギア＝歯、遺物＝二重刻印。色と形の二重符号化。
- 中央グリフ：効果を示す。例：胞子繁殖＝割れる胞子、共振破砕＝広がる3×3亀裂、自律機構＝2灯＋特殊駒、模倣の粘菌＝重なる二枚の刻印。
- 異種シナジー：円を単純に2色塗り分けるだけでなく、2系統の外周を噛み合わせ、中央に矢印または鎖を置く。
- サイズ：制作元は128px以上。表示はドラフト40px、プレイ36〜40px、用語シート64px。24px表示でも中央シルエットが潰れないことを条件にする。
- 実装初期は単色の線画グリフでもよい。20枚の完成イラストを待って情報設計を止めない。

所持ストリップのアイコンをタップすると詳細が開き、候補カードはその場に残る。詳細内に`この候補との接続`を追加し、所有物と候補を往復して比較できるようにする。強化が7個を超えたらアイコンを縮小せず、横スクロールにする。判別不能な小粒を10個詰めるより良い。

## [E] 優先実装計画

### 1. 勝敗情報へ画面を戻す — 必須、2〜4開発日

- プレイ中のスコアと大型ターゲット札を削除。
- 上部を`深度／油槽HP／メニュー`へ置換。
- 盤面、遭遇帯、ビルドドックを[A]の比率で再配置し、盤面とドックの間を最低8px空ける。
- 強化説明の欠けたラスター利用をやめ、仮でもコード描画の完全な枠へ差し替える。
- 375×667、390×844、430×932px、safe area有無でスクリーンショット確認。

期待効果は最も大きい。1秒見ただけでローグライクの現在地と危険が分かり、指摘5・6・7・8を同時に解消する。これはポリッシュではなく、ゲームルールの表示に関わる必須修正である。

### 2. 共通「野帳シート」とドラフト比較 — 必須、5〜8開発日

- 強化・特殊駒・敵・用語を同じボトムシートへ統合。
- プレイとドラフトの両方に所持強化ストリップを出す。
- キーワードをタップ可能なリッチテキストとして実装し、カード取得を確認ボタン式へ変更。
- ドラフトに`接続バッジ`と因果の一文を追加。
- 特殊駒4種、敵5種、上記の中核用語から辞書データを作る。

期待効果は、読解負荷と「何が起きたか分からない」を直接下げる。指摘1・2・3・4への本体対応であり、これも必須である。敵と強化で別のモーダルを増築すると後で必ず挙動差が出るため、共通コンポーネント化を先に行う。

### 3. 固有アイコンと状態演出 — 高価値のポリッシュ、アート3〜6日＋実装2〜3日

- まず20種を仮グリフで実装し、24pxで識別テスト。
- その後、ART.mdの暖色セピア・透明水彩・枯れた真鍮へ仕上げる。
- HPの油揺れ、低HPの炎、被弾予告領域、強化発火アイコンの点灯を追加。
- 初回特殊駒のコーチマークと、野帳内の小図を追加。

期待効果は記憶性、愛着、ビルドの「顔」の形成である。ただし、固有アイコンを先に美麗化しても、所持欄・比較・用語説明の構造がなければ価値を発揮しない。完成アートは第3段階でよい。

最終的な合格条件は、プレイ画面を3秒見た第三者が「7/10層、HPは約半分、次の攻撃まで2手、植物寄りの強化を5つ所持」と説明できること、ドラフト画面では10秒以内に「どの所持強化と、どの因果で接続する候補か」を説明できることである。現行は美術の魅力に対して情報の意味が追いついていない。ここを直せば、オーナー案の世界観を捨てずに、画面を現在のゲームへ正しく進化させられる。
