1. **高 — 詰み回避の再着色がイベント契約外で、盤面と表示が途中から食い違う。** `rerollSomePieces()` は通常駒を直接差し替えるだけでイベントを出さず（`src/core/board.ts:80-87`）、各手の連鎖後に呼ばれる（`src/core/board.ts:614-616`）。詰み盤面で再着色が走ると、以後の `match` / `fall` は新しい色を前提にする一方、`BoardView.play()` は古いテクスチャのまま処理し、終端の `reconcile()` まで誤色を表示する。また再着色自身が既成マッチを作っても解決されない。100回でなお手が無い場合もそのまま返るため、入力不能盤面が残る。

2. **高 — 連鎖段間の時間計算が落下完了を待たず、移動元で駒が消える。** `fall` は `t + T.pop` から最大 `T.fall` かけて動く（`src/view/BoardView.ts:317-333`）のに、次の chain の `match` では `T.chainBeat - T.pop - T.fall = 70ms` しか `t` を進めない（`src/view/BoardView.ts:234-242`）。例えば初段消去後に下段へ落ちた駒が即3連になると、その駒は落下開始の200msより前の70ms時点、すなわち旧座標で pop され、破棄済み Sprite に落下 tween も残る。`sprites` の帳簿だけはイベント順に先行更新されるため、見た目とセル対応が破綻する。

3. **高 — 胞子浮上後に盤面を再安定化しないため、穴・未解決マッチ・新たな詰みを次手まで残す。** 重力・補充・マッチ解決を終えた後で（`src/core/board.ts:607-617`）、`afterMove()` が胞子を空セルまたは通常駒と交換する（`src/core/board.ts:670-690`）。空セルとの交換なら胞子の旧位置が空いたまま、通常駒との交換なら移された駒が3連を作っても未消去になる。さらに詰み判定用の再着色も浮上前なので、浮上で唯一の有効手を壊した場合は永久に次の合法手へ進めない。これは斜めスライド未実装とは独立した問題。

4. **中 — 胞子だけは終端照合の対象外で、イベント取りこぼしを自己修復できない。** `reconcile()` は論理セルが胞子なら Sprite の有無・種類・位置を確認せず即 `continue` する（`src/view/BoardView.ts:383-409`）。例えば `spore-rise` 処理時に移動元 Sprite が既に欠けていると何もしない（`src/view/BoardView.ts:352-361`）うえ、照合でも胞子を再生成しないため、論理上は存在する胞子が以後ずっと不可視になる。逆に胞子セルに誤った通常駒 Sprite が対応していても残る。

5. **中 — 障害物の中間状態と多重ヒットを正しく描けない。** 苔石 HP2→HP1 の `block-hit(destroyed: false)` では再描画せず（`src/view/BoardView.ts:280-299`）、`reconcile()` も既存 Graphics の種類・HPを比較しない（`src/view/BoardView.ts:416-428`）ため、削れた苔石がHP2表示のまま残る。また銛×銛の交点などは同じセルを重複して `damageBlock()` できる（`src/core/board.ts:446-470`, `src/core/board.ts:491-499`）。匣→陶片→消滅が同一イベント列で起きると、同じ `gg` を破棄・再生成する遅延 callback が複数予約され、二重 destroy や孤児 Block の生成になり得る。

6. **中 — 連鎖ガード到達時は「消去直後」の不安定盤面を確定状態として返す。** `resolveCascades()` は各周回で重力・補充後にマッチを消し、50回目の `resolveMatches()` が真でもそのままループを抜ける（`src/core/board.ts:607-613`）。したがって最終消去でできた空セルには重力・補充が一度も適用されず、次の操作まで穴が残る。長い特殊連鎖や色数の少ない偏った盤面で発生すると、ビューの照合もその穴を正として固定する。

7. **中 — `finishWin()` は「残手数を全変換」の契約を満たさず、再入も防がない。** 13手以上残っていても12個だけ変換・減算した後、残りを無条件に0へ捨てる（`src/core/board.ts:713-734`）。通常駒候補が尽きた場合も `convertAt: null` のまま手数だけ消費するため、ブロック・胞子が多い盤面では期待する起爆数とスコアを失う。また一度だけ呼ぶ前提を状態で保証しておらず、二重呼び出しで `win-detonate-begin` を再発行する。加えて自動起爆探索は80回で打ち切るため（`src/core/board.ts:735-753`）、連鎖が特殊駒を作り続ける極端な盤面では特殊駒を残したまま勝利演出が終了する。
