## [B] The most serious remaining problem

最大の欠落は、**終盤へ向けて閉じた因果ループを組ませる強化設計と、それを確実に配る進行制御が存在しないこと**である。

今の20種には同時発火はあるが、自走ループとして信用できる経路が少ない。しかも、その少ない経路を構成する能力の一部が説明どおり動いていない。

- `磁気採掘` は「爆発に巻き込まれたギアが消えずに充填、次のギアマッチ2倍」と書くが、破壊後の `chargeGear` は単に `triggerGear` を呼ぶだけで、駒を残さず、充填状態も持たず、次のマッチも2倍にしない（`src/core/upgrades.ts:190-210`、`src/core/board.ts:1036-1045, 1251`）。
- `過回転` は盤面へ何も生まず、`self.chain += 1` で連鎖数の数字を増やすだけ（`src/core/upgrades.ts:228-231`、`src/core/board.ts:1258`）。これは「数値より挙動」という正典に正面から反する。
- `遺物共鳴` の2倍予約を消費するのは変換炉だけである。賭博師の壺、遺物の根、模倣の粘菌は `takeRelicBoost()` を呼ばない（`src/core/upgrades.ts:275-317`）。「次の遺物マッチが2倍」という説明は成立していない。
- ドラフトの2シナジー枠は、本物の因果辺ではなく同カテゴリ／同フック種で抽選される。必要なループ部品が終盤までに提示される保証がない。

その結果、終盤の派手さを作っている主役はビルドではなく、HP1 swarmの撃破伝播である。これは「自分が組んだ装置が走った」の代用品にならない。`r1_result.png` の最大連鎖1・発火6回という勝利記録は、演出を増やしても中身が自走していないことを示している。

閉じるために必要なのは、強化数を増やすことではない。まず20種を `入力資源 → 変換／生成 → 出力資源` の有向グラフとして再定義し、各系統に最低1本、2〜4枚で閉じるループを作ることである。次にドラフトをそのグラフで制御し、深度3までに起点、深度6までに二段接続、深度8までにループ閉鎖候補を必ず提示する。最後にイベントへ `sourceUpgradeId`、`sourceAt`、`resultAt[]`、`causedEventId` を持たせ、実際にどの辺が通ったかを記録・表示する。これがない限り、終盤の自己運転は偶然であり、再現可能な商品体験ではない。

## [D] Balance and progression

現状のままでは、20HP・10層で「序盤は普通、中盤で相乗、終盤で自走」という滑らかな曲線にはなりにくい。理由は、被ダメージが極端な同期バーストで、強化側は閉ループの保証がなく、しかも主要能力の数本が未実装同然だからである。

### 敵側

全層のswarm数は合計70体である。各個体は3手ごとに1ダメージを与える（`src/core/floors.ts:40-64`、`src/core/enemies.ts:30-42`）。つまり各層の最初の3手までに倒せなかった個体数が、そのまま同時被ダメージになる。

- 1層：6体残存なら3手目に6ダメージ。
- 2層：8体残存なら3手目に8ダメージ。
- 9層：10体残存なら3手目に10ダメージ。さらにクセ敵3体がいる。
- 回復手段は実装されておらず、20HPを10層で共有する。

ただしswarmは隣接ペアで、1体を倒すと相方も自動で倒れる。したがって実際の難度は「3手以内に各ペアへ一度触れればほぼ無傷、触れなければ6〜10ダメージ」という二値になる。これは圧力曲線ではなく、初期盤面運と敵近傍マッチの有無による事故判定である。サンドバッグが群れ全体で一斉にHPを削るのも役割に反する。

推奨値は次のとおり。

1. swarmの攻撃は個体ごとではなく群れ単位にする。`4体生存ごとに1ダメージ、切り上げ、1回最大3`。初回は4手後、以降3手ごと。これなら6体で2、8体で2、10体で3になり、数の圧を見せても20HPが事故で消えない。
2. 層構成を `3, 4, 5+岩殻, 6+胞子, 6+穴潜み, 7, 8+胞子, 8+穴潜み, 10+クセ敵2種, ボス+4` にする。1〜2層は本当に普通の3マッチを学ばせる。現行1層6体は入口から敵アイコンだらけで、原則に反する。
3. 3・6・9層クリア時にHPを2回復、最大20。合計最大6回復で、序盤事故を救いながらボス到達HPを8〜14程度に整える。回復強化がないMVPでは必要である。
4. ボス30HP・3手ごと3ダメージは据え置きでよい。ただしボス前HPが最低8以上になるよう上記の群れダメージと回復を先に直す。30HPを下げると完成ビルドの試運転時間まで消える。

### 強化側

ボス到達時は初期1個＋9回ドラフトで最大10個を持つ。枚数だけ見れば十分だが、現在の抽選は本物の接続を保証しない。さらに重複取得不可なので、同じ中核能力を強める縦成長もない。結果として10個が並列に小さく発火し、1本の装置にならない。

数値調整より先に、以下を行うべきである。

1. 初期配布を8種に限定する：`胞子繁殖／菌糸の目覚め／深呼吸（必ず非植物を変換するよう修正後）／採掘慣れ（説明と処理を統一後）／自律機構／予熱／変換炉／遺物の根`。賭博師の壺、4消し依存、前提物改造、コピー能力は初期から外す。
2. 深度2までのドラフトは、所持強化の出力を使う候補を最低1枚保証する。深度5終了時に二段因果がなければコネクタを1枚強制提示する。深度7終了時に閉ループがなければ、そのビルドのループ終端候補を1枚強制提示する。
3. ループ完成時の発火量目標を決める。深度1〜2は1手あたり強化発火0〜1回、深度4〜6は平均2〜4回・最大連鎖3〜5、深度8〜10は平均6〜12回・上位20%の手で連鎖8以上。現在の勝利画像のラン通算6回は、この目標の一手分にも足りない。
4. スターター量を前回値へ戻す。胞子1、爆発鉱石1、充填済みギア1、遺物共鳴予約1。2個配布は本体より強く見える。
5. `ギア起動2回` は据え置く。ただし磁気採掘と過回転を本当にギア起動へ戻す。自律機構＋機械庭園の2枚だけでも、2起動ごとに特殊駒1＋植物2が出るため中盤の見える相乗になる。
6. 植物の閉ループを確実にする。胞子繁殖の胞子2は据え置き、菌糸の目覚め1変換も据え置き。ただし胞子の基礎変換先を予測可能にし、変換で新マッチができた場合は必ず同じ解決内で再走査する。これで「植物を消す→胞子／植物が増える→自然マッチ」が成立する。

合格判定は勝率ではない。1000シードの自動プレイまたは半自動ボットで、深度別に `1手の自然連鎖数、強化発火数、因果段数、swarm由来撃破数、残HP` を記録する。swarm伝播はビルド発火から分離して集計しなければならない。
