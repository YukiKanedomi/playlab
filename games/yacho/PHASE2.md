## 1. ラン構造：**通し30層**（案B）

**決定**：30層を1本の縦坑として直列に作る。分岐制・中継地点制は採らない。

- **深度30への到達は難しくてよい**。「何回もプレイしてようやく到達」が狙いどおりの状態
- 深度10 / 20 / 30 にボス。**30層ボスの後に特殊ラスボス**
- 層あたりの難度は現行を維持する（到達率を上げるための難度緩和はしない）

### 到達率についての判断（記録）
Fable案は「現行クリア率39.2%の複利で深度30到達は6%。最も高価な資産を誰も見ない」として
中継地点方式を推したが、**オーナーは低到達率を意図された仕様として承認**した。

補足：現在の遭難分布は層5:4 / 6:4 / 7:11 / 8:17 / 9:14 / 10:23 で、中央値は層8〜9。
30層でも大半のランは中盤で終わるため、**典型的な1セッションは15〜25分**に収まる見込み。
40〜60分になるのは勝ちランのみで、これは稀。したがって長さの問題は主に**中断セーブ**で処理する。

## 2. 知見の枠（要実装・要計測）

**現状の問題**（実測）：発火/手が層1の0.60から層10の11.84まで**単調増加し頭打ちにならない**。
知見は取るだけで捨てることがないため、後半のドラフトが「どれを取っても強い」＝判断の消失になっている。
このまま30層へ伸ばすと1手30回以上発火し、読めない盤面になる。

**対策**：知見に**枠（初期8枠）**を設ける。枠が埋まった後の採録は「取る＝1つ捨てる」になる。

- 後半の採録がすべて判断になる
- 発火/手が頭打ちになり盤面が読める
- **呪いが「枠を1つ潰す」という代償として成立する**

**合否は数字で判定する**：①発火/手が深層で頭打ちになるか ②後半の採録で実際に入れ替えが起きるか。
runsim で計測し、効果が確認できなければ枠数を調整するか、この施策自体を撤回する。

## 2.5 難易度の狙い（2026-08-14 オーナー指示）

> 「**ぎりぎりクリアできないぐらい**にして、でも**次やったらいいビルドが作れる気がする**、
> なので**もう一回やりたい**。というローグライクの良さが出る感じにしたい」

これは「勝率を下げる」という指示ではない。**惜しい負けを量産する**という指示である。
文字どおり「絶対にクリアできない」にすると、単に理不尽で離脱する。狙いは次の3条件を同時に満たすこと。

### ① 惜しい負け方をする ＝ 遭難深度の分布を終盤へ寄せる
**測るべきは勝率ではなく「遭難した深度の分布」**。深度5で死ぬのと深度27で死ぬのでは意味が違う。

- 現状（10層）の遭難分布は 層5:4 / 6:4 / 7:11 / 8:17 / 9:14 / 10:23 で中央値は層8〜9＝**既に終盤寄りの良い形**
- 30層では **遭難深度の中央値20〜24／深度25以上での遭難が全体の35%以上** を目標にする
- **runsim の合格条件に「遭難深度の分布」を追加する**（勝率だけを見ない）。
  分布が平坦だったり序盤に山があれば、そのランは「惜しくない」＝再挑戦の動機が出ていない

### ② 敗因が自分の判断に帰せる
「運が悪かった」で終わると次のランの動機にならない。酸素0の遭難は静かに来るので、
**結果画面で「なぜ細ったか」を言語化**する。

- `深度18から酸素が細り始めた`（層ごとの補給前残酸素は既に記録できる）
- 直近の大きな損失を1件だけ名指す（例：`深度22 息喰みに3度触れた（-9）`）
- **責めない**。事実だけを書く

### ③ 実現しなかったビルドが見える【最重要・かつ安い】
「次やったらいいビルドが作れる気がする」の正体はこれ。**`core/draft.ts` の `closesLoop()` が既にある**ので、
「**あなたの構成は◯◯があれば輪が閉じていた**」を計算で出せる。新機構はほぼ不要。

- 結果画面に「**あと一つ**」欄：所持知見に対して、輪を閉じる候補を1〜2件提示する
- 「最も働いた知見」（層間リザルト）と対にすると、**働いたもの／足りなかったもの**が並ぶ
- これはメタ進行でも永続強化でもない。**情報だけ**なので、資源は酸素1本のまま

### ④ 再挑戦の摩擦を減らす
結果画面から**1タップで次のランを開始**できること。ホームやマップを経由させない。

## 2.6 アセンション（将来・バックログ）

> 「いつかはアセンションのような玄人向けの仕組みを追加してもいい」

採用する。ただし**基礎難度が上記の形（惜しい負けの分布）に収束してから**着手する。

  課目が常に2つ ／ 補給が-1 ／ 原生種が1体多い

## 5. 原生種のアート（最優先の実務）

**「敵に魅力がない」の実体は設計ではなく実装**であることが判明した。6種のうち5種が専用アートを持たない：

| 原生種 | 現在の描画 |
|---|---|
| 岩殻獣 | 苔石（障害物）テクスチャの流用＋コード描画の目 |
| 喰み蟲 | 巣灯（障害物）テクスチャの流用＋コード描画の目 |
| 裂坑掘り | コード描画の同心円＋目2つ |
| 息喰み | コード描画の同心リング |
| 深匣主 | 匣タイルの横並び |
| 小型胞子虫 | `e_swarm.png`（**唯一の専用アート**） |

生態設定を何行書いても、絵が障害物の流用のままでは魅力は出ない。
**原生種1体の納品単位**（Codex [B] §4）を守ること：
①全身の生態スケッチ ②盤上の正面／兆候／被弾の3状態＋idle ③採録帖1ページ（生息域・食性・兆候・対処・未観測欄）
④初遭遇の1.2秒の名前札 ⑤深度図のシルエットと危険度印。**これを満たさない敵は種類数に数えない。**

生成の作法は `ART_GRAMMAR.md` に従う（作品名・作者名・作中キャラ名・作中固有生物名をプロンプトに入れない）。
