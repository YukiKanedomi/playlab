## 1. ラン構造：**通し30層**（案B）

**決定**：30層を1本の縦坑として直列に作る。分岐制・中継地点制は採らない。

- **深度30への到達は難しくてよい**。「何回もプレイしてようやく到達」が狙いどおりの状態
- 深度10 / 20 / 30 にボス。**30層ボスの後に特殊ラスボス**
- 層あたりの難度は現行を維持する（到達率を上げるための難度緩和はしない）

### 到達率についての判断（記録）
Fable案は「現行クリア率39.2%の複利で深度30到達は6%。最も高価な資産を誰も見ない」として
中継地点方式を推したが、**オーナーは低到達率を意図された仕様として承認**した。

補足：現在の遭難分布は層5:4 / 6:4 / 7:11 / 8:17 / 9:14 / 10:23 で、中央値は層8〜9。
30層でも大半のランは中盤で終わるため、**典型的な1セッションは15〜25分**に収まる見込み。
40〜60分になるのは勝ちランのみで、これは稀。したがって長さの問題は主に**中断セーブ**で処理する。

## 2. 知見の枠（要実装・要計測）

**現状の問題**（実測）：発火/手が層1の0.60から層10の11.84まで**単調増加し頭打ちにならない**。
知見は取るだけで捨てることがないため、後半のドラフトが「どれを取っても強い」＝判断の消失になっている。
このまま30層へ伸ばすと1手30回以上発火し、読めない盤面になる。

**対策**：知見に**枠（初期8枠）**を設ける。枠が埋まった後の採録は「取る＝1つ捨てる」になる。

- 後半の採録がすべて判断になる
- 発火/手が頭打ちになり盤面が読める
- **呪いが「枠を1つ潰す」という代償として成立する**

**合否は数字で判定する**：①発火/手が深層で頭打ちになるか ②後半の採録で実際に入れ替えが起きるか。
runsim で計測し、効果が確認できなければ枠数を調整するか、この施策自体を撤回する。

## 2.5 難易度の狙い（2026-08-14 オーナー指示）

> 「**ぎりぎりクリアできないぐらい**にして、でも**次やったらいいビルドが作れる気がする**、
> なので**もう一回やりたい**。というローグライクの良さが出る感じにしたい」

これは「勝率を下げる」という指示ではない。**惜しい負けを量産する**という指示である。
文字どおり「絶対にクリアできない」にすると、単に理不尽で離脱する。狙いは次の3条件を同時に満たすこと。

### ① 惜しい負け方をする ＝ 遭難深度の分布を終盤へ寄せる
**測るべきは勝率ではなく「遭難した深度の分布」**。深度5で死ぬのと深度27で死ぬのでは意味が違う。

- 現状（10層）の遭難分布は 層5:4 / 6:4 / 7:11 / 8:17 / 9:14 / 10:23 で中央値は層8〜9＝**既に終盤寄りの良い形**
- 30層では **遭難深度の中央値20〜24／深度25以上での遭難が全体の35%以上** を目標にする
- **runsim の合格条件に「遭難深度の分布」を追加する**（勝率だけを見ない）。
  分布が平坦だったり序盤に山があれば、そのランは「惜しくない」＝再挑戦の動機が出ていない

### ② 敗因が自分の判断に帰せる
「運が悪かった」で終わると次のランの動機にならない。酸素0の遭難は静かに来るので、
**結果画面で「なぜ細ったか」を言語化**する。

- `深度18から酸素が細り始めた`（層ごとの補給前残酸素は既に記録できる）
- 直近の大きな損失を1件だけ名指す（例：`深度22 息喰みに3度触れた（-9）`）
- **責めない**。事実だけを書く

### ③ 実現しなかったビルドが見える【最重要・かつ安い】
「次やったらいいビルドが作れる気がする」の正体はこれ。**`core/draft.ts` の `closesLoop()` が既にある**ので、
「**あなたの構成は◯◯があれば輪が閉じていた**」を計算で出せる。新機構はほぼ不要。

- 結果画面に「**あと一つ**」欄：所持知見に対して、輪を閉じる候補を1〜2件提示する
- 「最も働いた知見」（層間リザルト）と対にすると、**働いたもの／足りなかったもの**が並ぶ
- これはメタ進行でも永続強化でもない。**情報だけ**なので、資源は酸素1本のまま

### ④ 再挑戦の摩擦を減らす
結果画面から**1タップで次のランを開始**できること。ホームやマップを経由させない。

## 2.7 資源を「酸素」から「灯」へ（2026-08-14 オーナー決定）

コンセプト検討で資源のゲージを「真鍮とガラスの管」にしたところ、**それが酸素である必然性が消えた**ため再定義した。

**決定：資源は「灯（あかり）」。探窟灯が燃やす、深界で採れる青く発光する液。**

| | |
|---|---|
| 資源名 | **灯**（あかり） |
| HUD表示 | **残灯　66** |
| 失敗 | **灯が尽きる**（「遭難」は使わない） |
| 補給 | 補給点で**光胞子**から灯を継ぐ（既存の `spore` 駒と接続する） |
| ゲージ | 真鍮とガラスの管。**青い液**が減っていく（横棒のバーは廃止） |
| 灯を奪う原生種 | 息喰み → **灯喰み** |

### なぜ灯なのか
1. 視覚の錨が既にある（ランタン。現ゲージ素材 `ui_oil` はそもそも油槽）
2. **奈落の本当の敵は暗さ**。プレイヤーは見て記録しに来ており、光が尽きる＝記録できなくなる
3. 原生種の設計が締まる（発光する種／光を食う種が意味を持つ）
4. 文体に合う（「灯が細り始めた」）
5. 既存の**光胞子**の駒と資源が接続し、「深く潜るほど奈落自身の光に頼る」が成立する

**機構は一切変えない**（1手で-1／0で終了／層クリアで補給／灯を奪う原生種は-3）。
`PLAN_LOOP.md §1.4` の仕様はそのまま有効で、**呼称と見た目だけを差し替える**。
コード上の識別子（`oxygen`, `OXYGEN_*`, `oxygen-drained` 等）は変更しない（表示文字列のみ）。

## 2.8 合成と深化（2026-08-15 実装。**オーナー未承認・要判断**）

> オーナー指摘：「固定枠だと**9回目以降の選択があまり楽しくない**」。
> 固定枠ローグライクの解法として「考えてみる価値がありそう」と述べられた**合成**と**深化**を、
> 元に戻せる形で実装したもの。**この節はまだ決定ではなく、朝に判断するための材料**である。

### 何を足したか

採録画面の行為が1つ（採る）から3つになる。上部に細い行為タブが出て、カード3枚の中身が入れ替わる。

| 行為 | 出る条件 | 枠 |
|---|---|---|
| **採る** | 常に | 埋まっていれば入れ替え |
| **合成** | 呼応する2つ（資源Rを生む知見＋Rを使う知見）を持っているとき | **1つ空く** |
| **深化** | 深化できる知見を持っているとき | 変わらない |

**合成**はペアごとに書くと50組を超えるので**資源ごとに1種類**の知見にまとめた（呼応の判定は既存の
`core/draft.ts` の consumes/produces をそのまま使う）。合成後の6種：

| 資源 | 合成後の知見 | 起きること |
|---|---|---|
| 胞子 | 胞子の環 | 胞子が消えると、そのマスととなり4マスが葉に変わる |
| 爆発鉱石 | 爆ぜる鉱脈 | 爆発鉱石が爆発すると、盤上の鉱物1つが新しい爆発鉱石になる |
| ギアの起動 | 回り続ける機関 | ギアが起動すると、となりの駒1つがギアに変わる |
| 特殊駒 | 絡繰の連なり | 4つ以上そろえて消すと、盤上のどこかに特殊駒が1つ生まれる |
| 植物の駒 | 苔むす坑道 | 植物をそろえて消すと、跡地の近くに植物が生え、そこに胞子がつく |
| 遺物の共鳴 | 共鳴の環 | 遺物をそろえて消すと、次の遺物マッチの効果が2倍になる |

- **7種ではなく6種**：資源「原生種へのダメージ」は**それを使う知見が1つも無い**（環が閉じない）ので合成が存在しない。
  将来それを使う知見を足せば、7種目が自然に生える
- 合成の知見は**採録の抽選に出さない**（合成でしか手に入らない）。結果画面の「あと一つ」にも出さない

**深化**は「発動条件を1段ゆるめる」だけで、数値は足していない（ROGUE2 原則3）。20種のうち**15種**に1文ずつ書いた。
例：`植物マッチ時→どの系統でも` / `4つ以上→3つ以上` / `キノコ限定→植物なら何でも` / `2回ごと→毎回` /
`原生種のとなり→最寄りの原生種`。**残り5種には深化が無い**（共振破砕・予熱・磁気採掘・蔓ロケット・胞子弾は
そもそも条件を持たない常時効果で、ゆるめる先が無いため）。

### 実装（元に戻し方）

- 中核は `src/core/fusion.ts`（合成・深化の規則）と `upgrades.ts` の `deepen` / `fusion` 欄、`RunState.deepened`
- **`fusion.ts` の `PHASE28_ENABLED = false` にするだけで、承認ずみの「採るだけ」の採録画面へ完全に戻る**
  （行為タブごと消える。知見側に残る deepen/fusion 欄はどこからも読まれなくなるだけ）

### 私が足した歯止め（**要判断**）

`FUSION_MAX = 2` / `DEEPEN_MAX = 3`（`fusion.ts`）。どちらも枠を食わずに強くなるため、上限が無いと
1ランで深化が14回選べてしまい、PHASE2 §2 の狙い（発火/手が深層で頭打ちになる）が完全に壊れる。
**正典に無い追加なので、数字を消せば無制限に戻せる。**

### 測った結果（120シード・同一シードで比較）

| | 採るだけ（承認ずみ） | 合成だけ | 深化だけ | 両方（上限2/3） | 両方（上限なし） |
|---|---|---|---|---|---|
| 遭難深度の中央値（目標20〜24） | **22** | 16 | 19 | 14 | 14 |
| 深度25以上の遭難（目標35%以上） | **37.5%** | 18.3% | 15.8% | 13.3% | 10.8% |
| 発火/手（深度11-15 → 21-25） | **8.8 → 10.3** | 19.4 → 33.3 | 16.0 → 36.8 | 18.2 → 36.0 | 20.5 → 55.3 |
| 深度30クリア率 | 5.8% | 30.8% | 62.5% | 40.8% | 45.0% |
| 後半の採録の内訳（採る/合成/深化） | 100 / 0 / 0 | 79 / 21 / 0 | 62 / 0 / 38 | 75 / 6 / 19 | 57 / 19 / 24 |

**読み方（正直に）**

1. **狙いどおりだったところ**：終盤の採録は実際に3つの行為に割れた（両方ONで 採る57%・合成19%・深化24%）。
   「9回目以降が全部同じ入れ替え」ではなくなった。「採る」を選んだ回に限れば入れ替え率は変わらず高い（92〜100%）
2. **壊れたところ**：**較正が全滅する**。遭難深度の中央値が22→14、深度25以上の遭難が37.5%→13%、
   発火/手は深層で3.5倍になり、PHASE2 §2 が枠を導入して得た「頭打ち」が消える。深度30クリア率は 5.8%→41%
3. **原因**：合成も深化も**枠を食わずに強くなる**。とくに合成後の知見が「元の2つ＋利息」の強さになっており、
   枠が1つ空くうえに効果まで上がる。深化も条件をゆるめる先が「どの系統でも」になる知見が多く、発火機会が数倍になる
4. 上限（2/3）を入れても止まらない。**上限では直らない＝効果側の設計を弱めるか、代償を付けるかのどちらかが要る**
5. 小さな注意：120シード中1件だけ `stuck`（有効手が尽きた）が出た。合成後の知見が盤面の色を大きく寄せる
   （例：回り続ける機関がギアを増やし続ける）ので、盤が一色に寄って手が無くなる局面がありうる。
   採るだけなら0件なので、合成を入れるなら要観察

### 判断していただきたいこと

- **A. このまま入れる**（面白さ優先。較正はこの後まとめて取り直す）
- **B. 入れるが代償を付ける**（例：合成・深化には灯を払う。資源は灯1本のままなので §7 に反しない）
- **C. 効果を弱めて入れる**（合成後の知見を「元の2つのうち強い方と同じくらい」まで落とす）
- **D. 入れない**（`PHASE28_ENABLED = false`。承認ずみの状態へ即座に戻る）

現状のコードは **A**（上限2/3つき）で置いてある。遊んでみて「終盤の選択が楽しくなったか」だけを見ていただき、
数字の帳尻はそのあとで合わせるのが順序として正しいと考えたため。

### 外部レビュー2回目の所見（2026-08-15・**材料であって決定ではない**）

Codex の全文は `assets_src/codex_night_p2_2.md`。**推奨は D**（いったん切って作り直す）。要旨は3つ。

- **呪い**：祝福と対になる代償。**隠しデメリットは作らない**。選択画面で利点と代償を同じ大きさで示す

### 「野帳」の扱い
参照シートの看板からは外し、**ラン結果画面の見出し**として残す（`野帳　深度17 まで`）。
測量士の実務語であり、タイトル『そろえて、しるす。』と直結するため語自体は捨てない。

### 表記ルール（Codex [A] §3 より採用）
- 課目は**残数**で書く：`植物標本　あと41`。`9/50` は逆算を強いるので廃止
- 兆候は**動作名＋残り手**：`亀裂 2`。酸素を奪う場合だけ `酸素−3` を朱で
- 知見カードは「観察名／起きること／採録時のおまけ」の三段。`条件／効果／獲得ボーナス／接続` という
  開発データの露出をやめる

## 5. 原生種のアート（最優先の実務）

**「敵に魅力がない」の実体は設計ではなく実装**であることが判明した。6種のうち5種が専用アートを持たない：

| 原生種 | 現在の描画 |
|---|---|
| 岩殻獣 | 苔石（障害物）テクスチャの流用＋コード描画の目 |
| 喰み蟲 | 巣灯（障害物）テクスチャの流用＋コード描画の目 |
| 裂坑掘り | コード描画の同心円＋目2つ |
| 息喰み | コード描画の同心リング |
| 深匣主 | 匣タイルの横並び |
| 小型胞子虫 | `e_swarm.png`（**唯一の専用アート**） |

生態設定を何行書いても、絵が障害物の流用のままでは魅力は出ない。
**原生種1体の納品単位**（Codex [B] §4）を守ること：
①全身の生態スケッチ ②盤上の正面／兆候／被弾の3状態＋idle ③採録帖1ページ（生息域・食性・兆候・対処・未観測欄）
④初遭遇の1.2秒の名前札 ⑤深度図のシルエットと危険度印。**これを満たさない敵は種類数に数えない。**

生成の作法は `ART_GRAMMAR.md` に従う（作品名・作者名・作中キャラ名・作中固有生物名をプロンプトに入れない）。

## 6. 着手順

1. **語彙置換**（実装ゼロの決定。全UI文言・glossary。これを先に済ませないと絵と文が誤った世界に固定される）
2. **課目の残数化**＋**層間リザルト**（Codex [D]：通常層は1.8秒・入力待ちなし。幕主のみ全画面）
3. **原生種の絵**（1体目＝裂坑掘り。納品単位を満たす）
4. **知見の枠**＋runsim で頭打ちの確認
5. **祝福／呪い**の実装（開始1＋ボス後2）
6. 深度11〜20（第二幕）／21〜30（第三幕）／特殊ラスボス
7. 深度図の再設計・中断セーブ

## 7. やらないと決めたこと

- 分岐マップ・中継地点方式（案A/C。**通し30層に決定**）
- 「深層印」への改名（祝福／呪いの語を使う）
- プレイヤーを「記録者」に改名
- バストの再設計
- 3つ星・スコア・コインの復活（酸素という唯一の評価軸を濁らせる）
- 新しい資源の追加（祝福用通貨・移動力・満腹度など。資源は酸素1本）
