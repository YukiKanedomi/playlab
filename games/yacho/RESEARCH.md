## 1. コアメカニクス仕様

### 盤面・基本ルール
- スワップ式マッチ3。縦横3個以上の同色ラインで消滅。
- 基本駒は **王冠・本・盾・葉** 系の最大4〜5色。RMは「基本色を減らして（最大5→4以下）マッチ機会を増やし、パズル難度より爽快感を優先」した（Naufal）。
- **同時マッチング**：盤面のアニメーション中でも次のスワップ操作を受け付ける（＝入力ロックしない）。「業界最速級のアニメーション速度」と並ぶRMの手触りの核（DoF）。
- **盤面再シャッフルなし**：手詰まり時のシャッフル演出を排除（Naavik）。⚠️手詰まりが起きない生成をどう保証しているかは要調査（おそらく詰み防止のリフィル制御）。
- レベル再挑戦時のローディングゼロ。ゴール表示のスワイプ操作も削除（DoF）。

### 特殊駒（4種）— 生成条件と効果

| 特殊駒 | 生成条件 | 効果 |
|---|---|---|
| **ロケット** | 4個一列 | 縦向き/横向きがあり、1行または1列を全消し |
| **プロペラ** | 4個 2×2正方形（Wiki実確認） | ランダムな障害物（目標）へ飛んで破壊。**離陸時に隣接駒も消す**。目標消滅時は別対象へ自動転向 |
| **TNT** | 5個 L字/T字 | 半径2マス（5×5相当）を爆破 |
| **ライトボール** | 5個一列 | 盤上で最多の色の駒を全消し（駒と入れ替えると其の色全消し） |

- **発動方法（Wiki実確認）**：特殊駒は「隣の駒とスワイプ」または**タップ**で発動。タップ発動が片手プレイのテンポを支える。

### 特殊駒コンボ表（Fandom＋公式ヘルプのスニペットより）

| 組み合わせ | 効果 |
|---|---|
| ロケット＋ロケット | 十字（1行＋1列）全消し |
| ロケット＋TNT | **3行＋3列**を消す大十字 |
| ロケット＋プロペラ | プロペラがロケットを運び、目標が多い行/列で起爆 |
| TNT＋TNT | 半径4マス相当の大爆発（約80マス） |
| TNT＋プロペラ | プロペラがTNTを運び、目標最多地点で起爆 |
| プロペラ＋プロペラ | プロペラ3個に増えて3つの目標をランダム破壊 |
| ライトボール＋ロケット | 盤上最多色の駒を**全てロケットに変換**して一斉起爆 |
| ライトボール＋TNT | 同様に全てTNTに変換 |
| ライトボール＋プロペラ | 同様に全てプロペラに変換 |
| ライトボール＋ライトボール | **盤面全消し**＋全障害物1層剥がし |

> 設計メモ：コンボは「地味→派手」の単調増加ではなく、**変換系（ライトボール系）が最派手**という階層。広告で映えるのはライトボール＋ロケットの一斉変換→連鎖起爆。

### ブースター（Wiki実確認）
- **事前配置型3種**：Rocket / TNT / Light Ball。選ぶと盤面にその特殊駒が置かれた状態でレベル開始。Lv32相当から解禁。連勝報酬「執事の贈り物」で無償付与→連勝維持の心理インセンティブ（Sezer）。
- **ゲーム中使用型4種**（すべて手数を消費しない）：
  - Royal Hammer：1マス破壊 or 障害物1層剥がし
  - Arrow：選択マスの**行**を消す＋障害物1層
  - Cannon：選択マスの**列**を消す＋障害物1層
  - Jester Hat：盤面シャッフル（※自動シャッフルは無いが、手動シャッフルはブースターとして課金対象化されている）
- RMの特徴：マッチ不成立時の強制ブースター使用を廃止。爆弾系を高頻度生成し「プレイヤーに有利」に倒す（DoF）。
- 我々の採用：**2種**（事前配置＝ロケット、ゲーム中＝ハンマー）。

## 2. 障害物

### 分類体系（Fandom Wiki の公式タクソノミー。全90要素・ブラウザで実取得）
| 系統 | 代表 | 消し方の原理 |
|---|---|---|
| **Layered**（占有・多層） | Box, Vase, Safe… | 隣接マッチ/特殊駒で1層ずつ。最大4層 |
| **Generator**（生産） | Mailbox, Magic Hat… | 隣接ヒットで目標物を排出。**規定数集めると自動で閉じる** |
| **Container**（格納） | Cupboard, Shelf… | 隣接ヒットで壊すと中身（Plate等）が目標として出る |
| **Upper Layer**（被さり） | Honey, Chain… | 隣接マッチで剥がす。下の駒は動かせない |
| **Lower Layer**（下敷き） | Grass, Jelly… | その上でマッチ。色により1〜2ヒット |
| **Consecutive / Downward / Special** | Bow Tie / Bird / Curtain… | 30レベルスコープ外。参考のみ |

- Chain・Honey・Ice は現行RMに実在（Naufal 記事の「氷系廃止」説は**誤りと確定**）。
- 層つき障害物は**層ごとに剥がれる専用アニメ**があり進捗が視覚化される。
- Generator の「必要数に達したら自動停止」はプレイヤー有利設計の代表例（DoF の指摘と一致）。

### RM実物の序盤導入順（Wiki実測・Element Number順）
| # | 要素 | 初出 | 系統 | 仕様 |
|---|---|---|---|---|
| 1 | Box | **Lv1** | Layered | 最大4層。隣接マッチ/特殊駒で1層ずつ破壊。落下しない |
| 2 | Grass | **Lv4** | Lower Layer | その上でマッチ or 特殊駒。色により1〜2ヒット |
| 3 | Cupboard | **Lv11** | Container | 隣接ヒットで壊すと中の Plate が目標に |
| 4 | Mailbox | **Lv21** | Generator | 隣接ヒットで封筒を排出。規定数で自動閉鎖 |

### 我々の採用4種（本家の導入順をそのまま踏襲。名前は世界観確定後）
Box型(Lv1)・Grass型(Lv4)・Cupboard型(Lv11)・Mailbox型(Lv21)。
→ 相互作用の型が「多層破壊・下敷き・格納・生産」と全て異なり、30レベルで4つの異なる学習体験を作れる。本家がこの順を選んだ理由もそこにあると推定。

## 3. レベルデザイン（定量）

### マクロ構造（Gamigion: レベル1〜100 実測）
- 5ワールド×各20レベル。新ステージエリアは Lv1, 10, 21, 41, 61, 81。
- 新ブロック（障害物）は Lv1〜91 にかけて11種を段階導入。**Lv11から10レベルごと**が基本周期（Sezer: 11, 21, 31, 41, 51…）。
- **導入レベルは新障害物単体のみ**で構成し学習に集中させる。以後、既出障害物と混合して複雑化。
- 10レベルごとにボーナスラップ（リラックス期間：ボーナスレベル or ミニゲーム）。報酬300〜700コイン。

### 難易度の定量目標
| 指標 | 値 |
|---|---|
| 通常レベルの平均試行回数 | **約1.2回** |
| Hardレベル（Lv39, 45, 49, 55, 65, 75, 85, 95） | 平均1.6回 |
| Super Hard（Lv59, 69, 79, 89, 99） | 最大2.5回 |
| 手数：序盤 Lv1〜20 | 30〜38手 |
| 手数：中盤 Lv21〜60 | 25〜30手 |
| 手数：終盤 Lv61〜100 | 23〜27手 |
| 難易度サイクル | 5レベル周期（1易→5難→リセット）。プラトーなし |

- 意思決定密度は序盤→終盤で約20%上昇。「緊張は上げるが不公平感は出さない」。
- **ニアミス設計**：Hard/Super Hardでも「あと数手で勝てた」状態で終わるよう設計（残り目標が僅かに見える）。敗北を運でなくスキルの問題と認識させる（Naavik）。
- 敗北時はキャラクターの悲しい表情＋「please continue」で損失回避を刺激（Naavik）。

### 論文の裏付け（Eckmann 2024）
- スワップ式はコラプス式（タップ消し）より一貫して難しい→**難易度の下振れに注意**（序盤は特に易しく）。
- 特殊要素（障害物）の数は少ないほど易しい。**序盤は特殊要素を薄く**、増やすときは相殺しあう組み合わせで滑らかに。
- 盤面の色を変えられる救済ギミック（ペイント系）は高難度レベルの安全弁になる。
- シールド系・時限爆弾系・成長系は後半に回すべき。ロック系は少量に留める。

## 4. メタ・経済

### メタ構造（Wiki実確認で確定）
- **1レベルクリア＝星1個（固定・購入不可）**。星をタスクに支払う→エリアの飾りが1つずつ完成。
- 全タスク完了→**エリアチェスト**（コイン報酬）→次エリア解放。
- RMの重要判断：**装飾の自由選択を廃止**（Homescapes系と違い、飾りは固定で進むだけ）。メタを「進捗表示」に徹底的に単純化した（Naavik）。→ 我々の「星で飾りが育つ簡易メタ」はこの設計と一致。そのまま採用。
- **動画実測（エリア1「Castle」）**：エリア=**6タスク**、タスク単価=**★1**（序盤）、タスクは**順次解放**（前のタスク完了で次がアンロック、完了済は緑チェック）。タスク実行で城の建設アニメが約2〜3秒流れる。「Area Progress 0/6」のバー表示。
- **星が足りない状態でタスクを開くと「Not Enough Stars!」ポップ**→レベルへ誘導。レベル→星→タスクの循環を明示的に教える。
- **レベル報酬の実測**：Level 1クリアで**+68コイン**（地図画面でコインが飛んで加算される演出付き）。

### コインの用途と獲得源（Wiki実確認）
- 用途：追加手数の購入／ブースター購入／（ライフ回復＝我々は不採用）
- 獲得：レベルクリア報酬／ボーナスレベル／エリアチェスト／イベント類（我々はクリア報酬＋エリアチェストの2系統に絞る）

### 経済（数値）
| 項目 | 値 |
|---|---|
| 追加5手の価格 | 900コイン相当（DoF 2021）。現金換算の基本価格 $2（業界最高、Naavik） |
| 追加手数の連続購入 | 段階的値上げ：$4.35 → $6.65 → $8.95（Naavik） |
| ボーナスレベル報酬 | 300〜700コイン |
| ゲーム中ブースター | 1回 数百コイン規模 ⚠️正確な価格は動画で確認 |
- 敗北→追加手数購入の提案が収益の核。クリア画面では獲得物を明細アニメで可視化。

### 我々の採用
- コイン経済：クリア報酬＋ボーナスレベル→追加5手（900コイン）・ゲーム中ハンマー購入。
- ライフ制・課金・広告：**なし**（決定済み）。

## 5. UX・ジュース（手触りの核）

- **速度が第一**：業界最速級のアニメ速度＋入力ロックなし（移動中も次操作受付）。
- プロペラの命中に**ヒットストップを入れない**（連打感を削がない）（Naufal）。
- 大きめの駒サイズで判別性を確保。盤と駒の**明度対比**が視認性の生命線——「わずかな灰色調整で大きな効果」（DoF）。
- 報酬・進捗は必ず**数字とアニメの二重表示**（コイン加算が飛んで貯まる等）。
- キャラクター（王様相当）が盤面の状況に表情で反応：通常/ピンチ/勝利。
- 勝利時：ファンファーレ＋花火＋残手数の特殊駒変換（⚠️RMの勝利シーケンス詳細は動画フレーム分析で採寸）。
### 演出タイミング実測値（プレイ動画 30fps フレーム分析。±1〜2フレーム＝±33〜66ms）

| 演出 | 実測値 |
|---|---|
| 駒の消滅ポップ（白パフ＋スパークル） | 約170〜230ms |
| 箱破壊のデブリ飛散 | 約270〜330ms（消滅より長い＝破壊の重み） |
| 落下（1〜3行）＋着地 | 約330〜430ms |
| 連鎖のビート間隔（ポップ→次のポップ） | 約600〜800ms |
| 盤面は演出中も入力を受け付ける | 確認済（記事とも一致） |

### 勝利シーケンスの構成（Level 1 実測。合計約15秒）

| # | 段階 | 長さ | 詳細 |
|---|---|---|---|
| 1 | 「ROYAL MATCH!」バナー | 約3秒 | 最終目標達成の瞬間。暗転＋ラッパ＋紙吹雪。退場は約300msのスケールアウト、暗転解除は約100ms |
| 2 | ヘッダー差し替え | 即時 | Target表示→Reward（コイン）表示に切り替わる |
| 3 | 残手数ドレイン | 約1秒 | 残22手が**1手あたり約30〜60ms**の超高速で減り、1手ごとに白い彗星が盤面へ飛び特殊駒に変換 |
| 4 | 自動起爆ラッシュ | 約5〜6秒 | 変換された特殊駒が順に起爆。コイン噴水＋Rewardカウンタが加算されていく |
| 5 | 星獲得ポップ | 約1秒 | 大きな星がバウンドで出現 |
| 6 | Well Done画面 | タップ待ち | 星＋クッション＋Continue |
| 7 | ロード中Tipsカード | 約2秒 | 次の特殊駒の作り方を図解（例：赤4個→ロケット）。ロード時間を教育に転用 |

> 核心：勝利の快感の主体は「バナー」ではなく**残手数ドレイン→起爆ラッシュの約7秒**。ここが広告で最も引用される瞬間でもある。手加減せず作り込む。

## 6. 実装リファレンス

- [PixiJS match-3 チュートリアル（dev.to, Roman Guivan）](https://dev.to/roman_guivan_17680f142e28/match-3-game-in-pixijs-103-juice-and-polish-3fff)：Tween.js（`performance.now()` で update）＋ Howler.js 構成。イージングは Exponential/Bounce 系。スケール 0.8→1.0 / 300ms のバウンス例。
- [Eckmann の Godot 版 Match-3 Toolkit（GitHub）](https://github.com/DanielEckmann/Match3Toolkit)：メカニクスの形式化の参考（flood fill でマッチ検出、駒はHP制で障害物と統一的に扱う設計が示唆的）。
- 盤面エンジンの設計方針：**駒・障害物を「HPを持つセル要素」として統一**し、マッチ/特殊駒は「ダメージ源」として抽象化する（論文の設計と一致。障害物の層剥がしも自然に表現できる）。
